# Web Jam Tool

Веб-инструмент для совместного музыкального творчества в реальном времени: **телефоны гостей превращаются в XY-тач-контроллеры**, а весь звук считает одна машина-**хост** (ноутбук или планшет). Никаких приложений — только браузер и общая сеть.

Полное техническое задание проекта лежит в [`PROMPT_CONTEXT.md`](./PROMPT_CONTEXT.md).

## Как это устроено

- **Хост** (десктоп или телефон) — держит аудио-граф и сам играет на том же XY-паде, что и гости: драм-машина на 16 шагов, пять инструментов (Pad, бас, орган, калимба, пианино). У каждого инструмента свои три эффекта, у драм-машины отдельная шина. Аудио-контекст стартует только по кнопке **Включить звук**.
- **Гость** (телефон) — полноэкранная тач-панель без скролла и зума. Ось X выбирает ступень тональности хоста. В аккордах ось Y выбирает диатоническое расширение (триада, sus, септ, нона). Бас всегда одна нота. Гость крутит эффекты своего инструмента так же, как хост. Код сессии вручную вводить не нужно: QR на экране хоста открывает контроллер сразу.
- **Сеть** — Socket.io: гость шлёт нормализованные координаты (`x`, `y` ∈ [0,1]), хост принимает и озвучивает вместе со своими касаниями. Сессии разделяются 4-символьным кодом.

Библиотеки с официальных CDN, все под MIT: [Tone.js](https://tonejs.github.io/), [Socket.io](https://socket.io/) и [QRCode.js](https://github.com/davidshimjs/qrcodejs) (`https://cdn.jsdelivr.net/gh/davidshimjs/qrcodejs@master/qrcode.min.js`). Весь код инструмента написан с нуля на стандартах W3C (Pointer Events, Web Audio, ES-модули). Сэмплы барабанов — отдельный бесплатный набор, не MIT: см. ниже.

## Локальный запуск

Нужен Node.js 18+.

```bash
npm install
npm run dev
```

Сервер поднимется на [http://127.0.0.1:43117](http://127.0.0.1:43117) (порт меняется переменной `PORT`).

1. На хост-машине открой корневую страницу и нажми **«Открыть экран Хоста»**, затем **Start Audio**.
2. В шапке — 4-символьный код, ссылка и QR. Ссылка внутри QR имеет вид `http://<ip-хоста>:43117/?role=controller&code=XXXX`: открытие сразу сажает гостя в контроллер, код руками не вводится.
3. Хост играет на своём XY-паде (те же касания, что и у гостя) параллельно с драм-машиной, эффектами и входящими тачами. На телефоне экран хоста тоже без скролла и зума: крупные кнопки пресетов вместо крутилок, 16 шагов секвенсора листаются страницами по 8.

Быстрые ссылки: `/?role=host` открывает экран хоста сразу, `/?role=controller&code=XXXX` — экран гостя.

## Структура

```
index.html            экран выбора роли + HOST view + CONTROLLER view
style.css             тёмная тема, крупные touch-элементы, no-scroll/no-zoom
server/server.js      Express + Socket.io: статика, сессии, роутинг тачей
src/main.js           роутер ролей, ленивые импорты модулей
src/views/host.js     сборка аудио-графа хоста и весь его UI
src/views/controller.js  экран гостя: тач-пад и переключатели
src/audio/engine.js   Tone.js контекст, мастер-шина, BPM
src/audio/drums.js    драм-машина, 16-шаговая редактируемая сетка
src/audio/synth.js    голоса Pad/Bass/Organ/Kalimba/Piano, лады, луп из нот
src/audio/effects.js  отдельные эффекты инструментов и драм-машины; Reverse на ScriptProcessor
src/ui/touch-pad.js   Pointer Events → нормализованные координаты, отрисовка
src/network/socket.js обёртка над Socket.io: сессии, тачи, управляющие события
scripts/perf-probe.mjs  замер CPU вкладок хоста и гостя через CDP
scripts/cpu-sampler.mjs замер CPU процессов Chrome из /proc
```

## Замер производительности

Стенд гоняет настоящий Chrome, открывает обе роли, включает звук и имитирует водение пальцем по панели, а затем печатает CPU каждой вкладки в покое и под нагрузкой:

```bash
npm install                 # puppeteer-core ставится как devDependency
npm run dev                 # в отдельном терминале
node scripts/perf-probe.mjs --url http://127.0.0.1:43117 --label after
```

Отчёт попадает в `/tmp/perf-<label>.json`: доля CPU (`cpuPercent` — время задач рендерера), частота кадров анимации (`rafPerSecond`), частота сообщений в сокет (`wsSendPerSecond` / `wsRecvPerSecond`) и число созданных аудио-узлов (`audioNodesCreated`). Параллельно можно запустить `node scripts/cpu-sampler.mjs` — он снимает CPU процессов Chrome прямо из `/proc`, включая отдельно главный тред рендерера.

Ключевые правила производительности, которые стенд стережёт: панель перерисовывается только по событию (никаких холостых rAF-лупов), тачи уходят в сеть не чаще 30 Гц и только при реальном изменении координат, а аудио-узлы создаются один раз при старте — на касание идут только триггеры и установка параметров.

## Барабаны: сэмплы TR-808

Kick, snare, hi-hat и clap грузятся с jsDelivr, пин версии пакета:

| Голос | Файл |
| --- | --- |
| Kick | `BD/BD0025.WAV` |
| Snare | `SD/SD2525.WAV` |
| Hi-Hat | `CH/CH.WAV` |
| Clap | `CP/CP.WAV` |

Базовый URL, который реально открывается из браузера: `https://cdn.jsdelivr.net/gh/fluid-music/open-drums/tr-808/TR808WAV/`.

Скоуп-адрес `https://cdn.jsdelivr.net/npm/@fluid-music/tr-808@0.0.2/TR808WAV/` указывает на те же файлы (пакет 0.0.2), но браузер кодирует `@` как `%40`, и jsDelivr отвечает 400. Поэтому плеер ходит в GitHub-CDN jsDelivr без символа `@`.

Источник — набор **Roland TR-808 sample set 1.0.0** (8 сентября 1994), записанный Michael Fischer / Technopolis напрямую с TR-808 (серийный номер 103852), 16-bit / 44.1 kHz. В сопроводительном `TR808.TXT` набор назван **ABSOLUTELY FREE**. Пакет [`@fluid-music/tr-808`](https://www.npmjs.com/package/@fluid-music/tr-808) (репозиторий [fluid-music/open-drums](https://github.com/fluid-music/open-drums/tree/main/tr-808)) пишет: «no licensing restrictions». Это не лицензия MIT и не CC — автор просто отдал записи без ограничений. Код инструмента при этом MIT.

Если CDN не отвечает за 4 секунды, голос остаётся на синтезе (Membrane / Noise / Metal), а на экране хоста пилюля явно говорит **«барабаны: синтез — CDN недоступен»** (или перечисляет голоса, которые не загрузились).

## Звук слоя и Reverse

Луп квантуется к сетке 1/16 `Tone.Transport` и хранит только ноты. Крутилки эффектов в буфер не пишутся: уже записанный луп слышен через текущие эффекты. Reverse стоит на пианино и сделан через `ScriptProcessor` (окно пишется и играется задом наперёд). На `http://` в локальной сети AudioWorklet недоступен, поэтому его здесь нет.

В клетке драм-машины три состояния: пусто → обычный удар → триоль внутри этой доли (на кнопке цифра 3) → снова пусто. Соседние клетки не сдвигаются.
