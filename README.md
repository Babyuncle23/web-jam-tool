# Web Jam Tool

Веб-инструмент для совместного музыкального творчества в реальном времени: **телефоны гостей превращаются в XY-тач-контроллеры**, а весь звук считает одна машина-**хост** (ноутбук, планшет или телефон). Никаких приложений — только браузер и общая сеть.

Полное техническое описание проекта лежит в [`PROMPT_CONTEXT.md`](./PROMPT_CONTEXT.md).

## Как это устроено

- **Хост** — держит весь аудио-граф и сам играет на том же XY-паде, что и гости: драм-машина на сетке 16/32/64 шага, пять инструментов (Pad, Bass, Organ, Kalimba, Synth). У каждого инструмента свои три эффекта, у драм-машины — отдельная шина (Dist/Cut/Room), поверх всего — мастер-эффекты (Stutter, Cutoff, 8-bit, Wah) и компрессор с лимитером. Аудио-контекст стартует только по кнопке **Start sound**.
- **Гость** (телефон) — тач-панель без зума. Ось X выбирает ступень тональности хоста. В режиме Chords ось Y выбирает диатоническое расширение (triad, sus2/sus4, септ, нона); лейбл аккорда считает та же функция `resolveGesture`, что и звук на хосте. Бас всегда одна нота. Гость выбирает инструмент и крутит его эффекты так же, как хост.
- **Сеть** — Socket.io: гость шлёт нормализованные координаты (`x`, `y` ∈ [0,1]) и контролы, хост озвучивает их вместе со своими касаниями. Сессии разделяются 4-символьным кодом; QR на экране хоста открывает контроллер сразу — код руками вводить не нужно. Лупы общие: хост рассылает ноты всех игроков в `host:state`, редактор **Notes** у всех показывает одну партию — чужие ноты помечены пунктиром, но редактируются так же (правки идут контролами на хост, который пишет их в луп владельца).

Библиотеки с официальных CDN, все под MIT: [Tone.js](https://tonejs.github.io/) 15.0.4, [Socket.io](https://socket.io/) 4.7.5 и [QRCode.js](https://github.com/davidshimjs/qrcodejs) с jsDelivr. Весь код инструмента написан с нуля на стандартах W3C (Pointer Events, Web Audio, ES-модули). Сэмплы барабанов — отдельный бесплатный набор, не MIT: см. ниже.

## Локальный запуск

Нужен Node.js 18+.

```bash
npm install
npm run dev
```

Сервер поднимется на [http://127.0.0.1:43117](http://127.0.0.1:43117) (порт меняется переменной `PORT`, лимит подключений — `MAX_CONNECTIONS`, по умолчанию 10).

1. На хост-машине открой корневую страницу и нажми **«Join as Host»**, затем **Start sound**.
2. В шапке — 4-символьный код, ссылка и QR. Ссылка внутри QR имеет вид `http://<ip-хоста>:43117/?role=controller&code=XXXX`: открытие сразу сажает гостя в контроллер. Для localhost сервер отдаёт LAN-IP через `/api/lan`.
3. Хост играет на своём XY-паде параллельно с драм-машиной, эффектами и входящими тачами.

Быстрые ссылки: `/?role=host` открывает экран хоста сразу, `/?role=controller&code=XXXX` — экран гостя.

## Публичная версия

Статика раздаётся с GitHub Pages; у такой страницы нет своего бэкенда, поэтому Socket.io-клиент переключается на сервер на Render — `PUBLIC_BACKEND_URL` в `src/network/socket.js` (`https://web-jam-tool.onrender.com`, держать в синхроне с именем сервиса). Локальные и LAN-адреса (`localhost`, `127.0.0.1`, `192.168.*`, `10.*`) по-прежнему ходят на тот же origin, что и страница.

Если сервер полон (`MAX_CONNECTIONS`), клиент показывает оверлей «Server is full» и сам ретраит, пока место не освободится.

## PWA

`manifest.json` + `sw.js` делают страницу устанавливаемой: на экране ролей есть кнопка «Install App to Home Screen» и QR со ссылкой на эту страницу. Service worker ничего не кэширует — джему всё равно нужен живой бэкенд.

## Драм-машина: сэмплы TR-808

Семь голосов грузятся с jsDelivr (GitHub-CDN, без `@` в URL — scoped npm-адрес отвечает 400):

| Голос | Файл |
| --- | --- |
| Kick | `BD/BD0025.WAV` |
| Snare | `SD/SD2525.WAV` |
| Hi-Hat | `CH/CH.WAV` |
| Clap | `CP/CP.WAV` |
| Open Hat | `OH/OH75.WAV` |
| Tom | `MT/MT25.WAV` |
| Cowbell | `CB/CB.WAV` |

Базовый URL: `https://cdn.jsdelivr.net/gh/fluid-music/open-drums/tr-808/TR808WAV/`.

Источник — набор **Roland TR-808 sample set 1.0.0** (Michael Fischer / Technopolis, 1994), названный в `TR808.TXT` **ABSOLUTELY FREE**; пакет [`@fluid-music/tr-808`](https://www.npmjs.com/package/@fluid-music/tr-808) пишет «no licensing restrictions». Это не лицензия MIT — MIT относится к коду инструмента.

Если голос не загрузился за 4 секунды, он остаётся на синтезе (Membrane / Noise / Metal), а пилюля на экране хоста говорит, какие голоса на сэмплах, какие — на fallback. У clap начало файла подрезается до пика, чтобы удар сидел в сетке.

## Луп, редактор Notes и Reverse

Луп квантуется к сетке 1/16 `Tone.Transport` (`scheduleRepeat`) и хранит только ноты; длина — 1, 2 или 4 бара (кнопка циклит 2 → 4 → 1). Эффекты в запись не попадают: луп слышен через текущие ручки. Аккорды сохраняются группой степеней лада.

Редактор **Notes** — общий у хоста и гостей: тап по пустой клетке внутри лада ставит ноту, тап по ноте удаляет, драг двигает, правый край меняет длительность, режим «select and move» — выделение и перенос группы. Undo / Undo all / Redo и очистка по инструменту (`clr curr inst`) — общие для всей партии.

Reverse стоит у калимбы: `ScriptProcessor` пишет хвост и играет его задом наперёд. На `http://` в LAN AudioWorklet недоступен, поэтому его в живом тракте нет.

В клетке драм-машины три состояния: пусто → удар → триоль внутри этой доли (цифра 3) → пусто. Repeat Off/1/2 бара зеркалит первые бары на остальные шаги.

## Экспорт

Кнопка **Export** на хосте: луп ×N повторов (1–128).

- **MIDI** — SMF-файл (PPQ 480): ноты всех инструментов по каналам, барабаны на канале 10.
- **WAV** — офлайн-рендер (`Tone.Offline`, 44.1 кГц стерео) той же цепочки, что и живой тракт: инструменты и барабаны → master → compressor → masterFx → limiter. Учитываются mute/solo, уровни и текущие master-эффекты.

## Замер производительности

Стенд гоняет настоящий Chrome, открывает обе роли, включает звук и имитирует водение пальцем по панели, а затем печатает CPU каждой вкладки в покое и под нагрузкой:

```bash
npm install                 # puppeteer-core ставится как devDependency
npm run dev                 # в отдельном терминале
node scripts/perf-probe.mjs --url http://127.0.0.1:43117 --label after
```

Отчёт попадает в `/tmp/perf-<label>.json`: доля CPU (`cpuPercent`), частота кадров (`rafPerSecond`), частота сообщений в сокет (`wsSendPerSecond` / `wsRecvPerSecond`) и число созданных аудио-узлов (`audioNodesCreated`). Параллельно можно запустить `node scripts/cpu-sampler.mjs` — он снимает CPU процессов Chrome из `/proc`. Остальные скрипты в `scripts/` — сценарные пробы: `jam-scenario.mjs`, `verify-drums.mjs`, `verify-shared-notes.mjs`, `stuck-note-probe.mjs`, `transport-sync-probe.mjs`, `screenshot-ui.mjs` и др.

Ключевые правила производительности: панель перерисовывается только по событию (никаких холостых rAF-лупов), тачи уходят в сеть не чаще 30 Гц и только при реальном изменении координат, аудио-узлы создаются один раз при старте — на касание идут только триггеры и установка параметров.
