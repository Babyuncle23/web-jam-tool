# Контекст проекта: DoggoJam — Real-time Web Jam Tool (Clean Room Implementation)

> Этот файл — снимок ТЕКУЩЕГО состояния кода. Если текст расходится с кодом — верен код; обнови этот файл в той же правке. Удалённое из кода удаляй и отсюда. Исключение — секция «Убрано — не возвращать» в конце.

Веб-инструмент для совместного музыкального творчества: телефоны гостей — XY-тач-контроллеры, весь звук считает одна машина-хост. Ниже — описание фактической архитектуры кода, а не пожелания.

## 1. Стек технологий
- Frontend: HTML5, CSS3, Vanilla JS (ES-модули), Pointer Events. Никаких фреймворков и сборщика.
- Audio Engine: Tone.js 15.0.4 (`https://cdn.jsdelivr.net/npm/tone@15.0.4/build/Tone.js`). Работает ТОЛЬКО на Хосте; на телефонах гостей аудио-код даже не импортируется (ленивые импорты в `src/main.js`). Сам скрипт не стоит в `<head>` — `enterHost()` грузит его через общий `loadScript` до `import('./views/host.js')` (host.js читает `globalThis.Tone`), кнопка «Open host» крутит спиннер (`is-loading`), ошибка → `join-error` на экране ролей. Прогрев идёт при входе в host-экран, а не по «Start sound» — скачивание не требует жеста, а тап не ждёт сеть. Гость Tone не грузит: `controller.js` и его импорты не трогают `globalThis.Tone` (константы из `audio/*` — без обращения к глобалу; `AudioEngine` читает его только в конструкторе).
- Real-time/Network: Socket.io 4.7.5 — клиент с CDN (`cdn.socket.io`, единственный синхронный `<script>` в `<head>` — нужен обеим ролям), сервер `socket.io` в `server/server.js`. В `<head>` — `preconnect` к `cdn.jsdelivr.net` и `cdn.socket.io`.
- Server: Node.js 18+, Express 4 + `compression` (gzip/br); статика — whitelist (`/`, `index.html`, `style.css`, `manifest.json`, `sw.js`, `/src`, `/icons`, `/samples`; всё остальное, включая `node_modules`/`scripts`/`*.md` — 404). Порт 43117 (env `PORT`), лимит подключений `MAX_CONNECTIONS` (по умолчанию 10) с экраном «Server is full» и авторетраем.
- QR: QRCode.js (davidshimjs) с jsDelivr, подгружается лениво через `loadScript`. После рендера канвас библиотеки синхронно заменяется на `<img>` из `toDataURL` — штатный async-свап qrcode.js (проба data-URI) может не сработать, тогда сырой canvas остаётся на своём нативном размере (168/512px), вылезает за карточку и QR не сканируется. В CSS `canvas` включён в те же селекторы размера, что и `img`/`table` — страховка, если свап не случится.
- PWA: `manifest.json` + `sw.js` (service worker-заглушка: fetch-обработчик пуст — нужен только для критерия installable, запросы идут в сеть напрямую), кнопка «Install App to Home Screen».
- Деплой: локально/LAN — Socket.io на той же машине, что и страница; публичная сборка (GitHub Pages) ходит в бэкенд на Render: `PUBLIC_BACKEND_URL = https://web-jam-tool.onrender.com` (`src/network/socket.js`).
- Target Devices: мобильные браузеры (Гости-контроллеры), десктоп/планшет/телефон (Хост).

## 2. Структура файлов проекта
- `/index.html` — экран выбора роли (галочка «Lite mode» в карточке хоста, кнопка «AI use disclosure» → шит `#ai-disclosure` с текстом об использовании ИИ при разработке) + разметка экранов HOST и CONTROLLER (все шиты, сплэши, оверлей «Server is full»).
- `/style.css` — единая тёмная тема «вечерний лес»: глубокий зелёно-чёрный фон, моховые карточки, тёплый светлый ink для текста и границ, приглушённый янтарь как акцент (светлой темы нет). Семантические переменные: `--ink`/`--line` — текст и границы, `--on-accent` — тёмный текст на насыщенных заливках (янтарные чипы, solo), `--text-on-color` — светлый текст на цветах инструментов, `--ink-rgb`/`--shadow-rgb`/`--bg-rgb`/`--sun-rgb`/`--plant-rgb` — RGB-тройки для `rgb(var(--x) / α)`, `--row-blocked` — недиатонические ряды ролла, `--sampler-hit` — вспышка пэда сэмплера. Цвета инструментов/дорожек (--row, --inst, FX_COLORS, INSTRUMENT_COLORS) остаются насыщенными и общими для CSS и канваса; мягкие подложки шагов `--row-soft` считаются через `color-mix(--row 20%, --bg-elevated)`. Крупные touch-элементы, no-zoom; на контроллере страница скроллится вертикально, тач-пад — нет. Три раскладки главных экранов: **портрет телефона** — `.host-app`/`.screen--controller` flex-колонна, у хоста `.host-tools` стоит `display:contents`, чтобы `.tempo-panel` (порядок 2) всплывала между `topbar` и `play-bar`, а секции шли под падом; **десктоп** (`min-width:1024px and min-height:640px`) — CSS-grid: `topbar`+`play-bar` на всю ширину, слева `pad-stage` на остаток высоты, справа скроллящаяся колонка `.host-tools`/`.controller-foot`; **landscape телефона** (`orientation:landscape and max-height:560px and pointer:coarse` — десктопное окно сюда не попадает) — grid 7fr/3fr (пад занимает ~70% ширины): верхние бары (`.topbar` у хоста, `.controller-bar` у гостя) скрыты полностью — JS переносит Back и Play в `.play-bar` (между чипами Notes/Chords и Rec; Play/Rec/Notes/Chords/sampler-Edit — квадратные icon-only кнопки (иконки Notes/Chords: восьмая нота vs три ноты на одном стебле, чипы подписаны иконками через paintIconButton)), в FX-режиме плей-бар прячется вместе с ними; справа скролл-колонка. Настройки живут в сворачиваемых `.tool-sec` (заголовок `.tool-sec__head` — div, не button: с него стартует скролл страницы; `.tool-sec__value` — сводка текущего значения, `.tool-sec__mini` — карусель инструмента в свёрнутом виде). Инструменты — сетка `.inst-list` (`auto-fill minmax(168px,1fr)`, в landscape телефона — простой список; на тач-устройствах и ≤700px секция стартует свёрнутой в карусель) из `.inst-card` (безбордерный pick с именем+свотчем, выбранная карточка `.is-on` заливается цветом инструмента через `--inst`, у хоста `.inst-card__mix` с S/M, `.inst-card__more` → FX-шит этого инструмента; в lite MORE прячет `.is-lite`). Чипов уровней FX нет вообще — настройка только через MORE-шит. Edit notes — компактная кнопка `.tool-sec__edit` в шапке секции инструментов рядом со сводкой; клики по контролам внутри шапки не сворачивают секцию. Скролл: `touch-action: pan-x pan-y` у всех кнопок/чипов/карточек — вертикальный (и горизонтальный в `.chips--scroll`) свайп с любого контрола скроллит страницу, тап срабатывает как клик; `touch-action:none` осталось только у жестовых поверхностей (`.pad`, `.roll__key`, `.roll__note`, `.sampler-pad`, `input[type=range]`), `.step` — `pan-y`. Мобильный хост: высота пада задана в `.pad-stage .host-pad` (56vh, min 300px), у гостя — `.pad-wrap` (56vh, min 280px) — специфичность обязана перекрывать `.pad {height:100%}`, иначе пад схлопывается до интринсик-высоты канваса; на ≤480px `.play-bar` переносится: Rec/undo/redo/clr на первой строке, пара Notes/Chords — на второй (order:2, прямо над падом); пресеты драмов (`.drum-presets`) всегда переносятся (`flex: 1 1 84px` — на узких колонках ломаются в несколько рядов). Stage-шиты (`.fx-sheet--stage`): карточка сама скроллится (`overflow-y:auto`), у `.sequencer` стоит `min-height` — иначе при открытой панели Advanced (драм-FX слайдеры) сетка сжималась флексом до нуля и клетки переставали кликаться.
- `/server/server.js` — Express + Socket.io: `compression`, whitelist-статика, `/api/lan` (LAN-IP для QR), сессии по 4-символьным кодам, роутинг тачей/контролов, гейт по числу подключений.
- `/src/main.js` — роутер ролей, ленивые импорты вью, ленивая загрузка Tone.js в `enterHost()` (спиннер `is-loading` на кнопке, ошибка → `join-error`; скрипты с CDN — через `loadScript(src, timeout)` с таймаутом, иначе зависшая загрузка висела бы вечно), `?role=host` / `?role=controller&code=XXXX`, регистрация SW. Каждая попытка входа инкрементит `entryToken`: устаревший результат/ошибка асинхронной инициализации не может сбросить экран, который уже заняла новая попытка (раньше вылет на экран ролей случался дважды подряд), а поздно разрешившийся вью после «назад» уничтожается — иначе его комната оставалась бы жить за скрытым экраном. Если клиент Socket.io не поднялся из `<head>`-скрипта (404 на публичной странице), `ensureSocketIo()` догружает его с бэкенда (`socketServerUrl()/socket.io/socket.io.js`). Режим хоста выбирается галочкой `#role-lite` до входа: автодетект слабого железа (`hardwareConcurrency`/`deviceMemory` ≤ 4) лишь предустанавливает галочку, `?lite=1`/`?lite=0` перекрывает; `enterHost(lite)` передаёт `LITE`-флаги в `createHostView`, а подпись кнопки переключается «Open host» ↔ «Open host — Lite». Кнопки «назад» (`[data-action="back"]` в обоих экранах) закрывают сессию только по удержанию ~700 мс или по второму тапу в окне 1.8 с — одиночный тап лишь подсвечивает кнопку `is-arming` (та же механика, что у clear-all), свод пальца или истёкшее окно снимают подсветку. Обработка делегирована на документе: `resetScreen` подменяет экраны целиком, собственный обработчик кнопки не пережил бы пересоздание.
- `/src/views/host.js` — сборка аудио-графа хоста и весь его UI (принимает `lite`-флаги: `createHostView({ lite })`, граф собирается урезанным, `lite` уходит и в `AudioEngine` — 24 кГц/`lookAhead`, — и в `TouchPadRenderer.maxRatio`/`TouchPad.throttleMs`; `host:state` несёт `lite: true`, в шапке пилюля `lite`): XY-пад с режимами Keys/SMP/FX (data-padmode: notes/sampler/fx) (пять X-зон: левая — только фильтр без статтера, дальше Stutter 1/4–1/32; Y биполярный — выше середины high-pass, ниже low-pass, середина — байпас; отпускание гасит статтер и открывает фильтр; в FX-режиме весь `.play-bar` (Notes/Chords + Rec/undo) прячется ради места под пад, при басе прячется только селектор Notes/Chords — аккордов у баса нет), драм-шит, Notes-шит, Master-шит (8-bit/Wah/громкость; в lite — только громкость), экспорт, приём тачей и контролов гостей, рассылка `host:state`/`host:pulse`. Биполярный фильтр мастера имеет владельца (`filterHolder` — `'host'` или peerId последнего движения cutoff/hipass): уход гостя-владельца посреди жеста (`peer:leave`, реконнект комнаты) открывает фильтр, чужой уход — нет. Флаг статтера у хоста тоже читается с движка (`masterFx.holding()`), а не из `state.masterFx.hold`: захват мог отвалиться mid-schedule, и тогда зеркальный флаг навсегда глушил статтер на тачпаде — погасшие флаги сейчас вычищаются тем же путём. Если сессия так и не открылась (`createSession` бросил), `abortBoot()` гасит пад/сетку/рендерер/таймеры и отсоединяет сокет — на сервере не остаётся висящего подключения. Раскладка главного экрана: `.host-tools` = `.tempo-panel` (`#btn-bars` + `#bpm-presets`) → `.tool-sec` «Key & scale» (`#sec-harmony`, свёрнута) → «Instrument» (`#sec-instruments`, карточки `#instrument-row .inst-card` с pick/S-M/MORE; свёрнутая — карусель `.inst-carousel` с `[data-inst-cycle]`) → «Drums» (`#sec-drums`, пресеты `#host-drum-presets` + S/M + `#btn-drums`) → `#btn-master` → `#host-log` последним. Сводки в заголовках красит `paintSecValues()` (`#sec-harmony-value`/`#sec-inst-value`/`#sec-drums-value`), карусель — `paintInstrumentMini()`; сворачивание — делегированный клик на `.tool-sec__head` (заголовок — div, скролл страницы с него работает). MORE карточки и выбор инструмента открывают `#host-fx-sheet` через `openFxSheet(instrument)` — слайдеры крутят `state.fxFor`, заголовок `#host-fx-title` зовёт инструмент по имени. Драм-FX — слайдеры `#host-drum-fx` внутри панели Advanced драм-шита (`renderDrumFx`; в lite пусто). В landscape телефона topbar скрыт: `placeLandscapeChrome` (matchMedia change) переносит `#btn-transport` и Back в `#play-bar` и возвращает обратно при повороте. В lite на `#host-screen` вешается класс `is-lite` — CSS прячет `.inst-card__fx`/`.inst-card__more`. Смена инструмента не останавливает запись и не сбрасывает режим пада/аккорды — выбор остаётся там, где его оставил пользователь; удерживаемый палец привязан к инструменту момента касания (`padFingers` у хоста, `fingerInstruments` у гостя + `instrument` в каждом тач-пэйлоаде), поэтому move/up старого пальца не переписываются на новый инструмент и не ставят аккордовых нот. Хит сэмплера — включая прилетевший от гостя — никогда не сбивает удерживаемый FX-статтер/фильтр: режимы пада взаимоисключающие, значит держит жест чужой палец на другом устройстве (старое `knockFxHold` убрано). Пока тейк открыт, `.pad.is-recording` перекрашивает центральный `.pad__pulse` в красно-розовый (та же beat-анимация `pad-beat`, класс ставится из реального флага рекордера — у хоста `paintRecButton`, у гостя `setRecording` и синк `recording` из `host:state`).
- `/src/views/controller.js` — экран гостя: тач-пад, Notes/Chords, Rec — на переднем плане; `.controller-foot` несёт сворачиваемые секции «Instrument» (карточки `.inst-card`: pick + MORE; свёрнутая — карусель `[data-inst-cycle]` + `[data-inst-name]`) и «Drums» (пресеты `#controller-drum-presets-main` + `#controller-drums`), в конце — кнопка `#controller-master`, открывающая мастер-шит (8-bit/Wah/громкость; в lite — только громкость). Отдельного шита «Advanced» нет: MORE у карточки открывает общий `#controller-fx-sheet`, нацеленный на инструмент карточки (`state.fxFor`; слайдеры громкости, октавы и эффектов этого инструмента). У пада тот же переключатель Keys/SMP/FX: FX-жесты летят на хост как `masterFx`/`masterHold` контролы по `controller:control`: `masterHold` (фронт статтера) и финальный сброс фильтра на отпускании пальца — надёжно через `sendControl`, движения биполярного фильтра `masterFx` — через `sendControlThrottled` (тот же путь у всех слайдеров шитов). Лад у гостя не выбирается — только отображается в шапке (задаёт хост). Зеркала драм-сетки и Notes-редактора (правки уходят контролами на хост). Из `host:state` гость читает и `lite`-флаг (класс `is-lite` на `#controller-screen`): на lite-хосте `instrumentFxSpecs`/`drumFxSpecs` возвращают пустые списки — FX-чипов и FX-слайдеров нет, но кнопка MORE остаётся: в шите всегда живут слайдеры громкости и октавы. `masterFx.hold` у гостя синкается с эхо `hold:false` даже посреди его жеста — иначе украденный/сброшенный хостом холд оставлял локальный флаг включённым и статтер молча не срабатывал, пока палец едет. На `host:state` гость отвечает дёшево: `renderGuestFx` — только при реальном изменении `effects` или открытом FX-шите, `syncPadMarks` — при изменении `loopNotes` (у `loopNotes` счётчик `v` — повторное эхо той же версии пропускает пересборку нот и репейнты, флаги undo/rec всё равно обновляются), `applyHostDrums` диффит payload поклеточно и при отсутствии изменений не трогает DOM вообще.
- `/src/audio/engine.js` — Tone.js контекст, мастер-шина (`Gain → Compressor → masterFx → Limiter(-2)`; гейн — `state.masterFx.volume`, дефолт `DEFAULT_MASTER_GAIN` = 0.78, крутится слайдером в Master-шите), BPM, `lookAhead = 0.02`, duck/restore при уходе вкладки в фон. `start()` только по жесту «Start sound».
- `/src/audio/synth.js` — голоса инструментов, лады, аккорды, `resolveGesture` (единая функция «палец → ноты/лейбл» для хоста и гостя), `PerformanceRecorder` (лупы на `Tone.Transport`), `padNoteMarks` (луп-ноты → точки-марки на тач-паде). `TouchSynth` принимает `lite` (флаги LITE): `lowPolyphony` меняет пулы на pad 8 / organ 8 / kalimba 4 / synth 6, `singleFat` ставит `count: 1` у fat-осцилляторов пада и баса.
- `/src/audio/drums.js` — драм-машина: 7 дорожек, сэмплы TR-808 с jsDelivr + синтез-fallback, сетка 16/32/64 шага, триоли, пресеты (элемент паттерна — шаг или `{ s: шаг, d: 3 }` для триоли, раскладку по длине делает `tileCells`), repeat, общий pitch ±12 полутонов (`setPitch`, `playbackRate = 2^(pitch/12)`, у синтез-голосов — shift частоты).
- `/src/audio/sampler.js` — пэд-семплер хоста: `SAMPLE_BANK` (хардкод id/лейбл/`mode: oneshot|gate`), раскладка `SAMPLER_PAD_CELLS` (4×3 — сейчас заполнена полностью: 11 пэдов + ячейка `solo`; пустой объект — резервный слот), `PadSampler` — пул по 3 `GrainPlayer` на сэмпл (`stretch` — множитель ДЛИТЕЛЬНОСТИ: ×2 = вдвое длиннее/медленнее, в `playbackRate` уходит `1/stretch`; `detune` — питч без длины), per-pad чок: повторный триггер гасит ТОЛЬКО свои звучащие слоты (фейд на per-slot `Gain`, не `player.stop` — иначе отложенный stop съедал бы свежий start; перед `start` слоту дают `stop(when)`, чтобы вытеснить ожидающий stop прошлого голоса; `onstop` слота с гардом `player.state === 'started'` — при рестарте ещё играющего слота onended старого голоса прилетал уже после start нового и стирал его флаги: voice терялся из release/choke и играл до конца буфера (баг «gate играет после отпускания и стакается»); choke/releasePad/stopSlot поэтому смотрят не только `sounding`, но и реальный `player.state`), `setParams` крутит уже звучащие слоты, `releaseMatching(prefix)`/`stopAll()` для очисток, `releasePad(id)` — отпускание пальца с gate-пэда (не трогает слоты `loop:`-голосов). Пэды со `spec.bpm` (SCR 105 — скрэтч с Pixabay, `mode: 'gate'`) жёстко прибиты к темпу: `stretch = spec.bpm / sessionBpm` через `setBpm()` (в т.ч. на старте и в конструкторе), стретч у них не тюнится — `setParams` игнорирует `stretch`, в панели слайдер залочен («locked to … BPM»), а бейдж `×N` на пэде не рисуется (это фит под темп, не настройка юзера); хост зовёт `syncSamplerBpm()` при старте аудио и на каждой смене BPM, обновлённые параметры уходят гостям в `host:state`. На загрузке буфер сканируется на онсет (`onsetSeconds`, порог ~−38 dBFS + 5 мс backoff) — стартовая тишина/mp3-задержка режется оффсетом в `player.start` — и на пик (`peakAmplitude` → `pad.vol`, нормализация к ~0.62, clamp ×0.25–×4 — одинаковая громкость пэдов; `spec.gain` — доп. трим). Каждый пэд проходит свой high-pass `filter` (база 120 Гц, у BEAT `spec.guardHz`=45 — бум-бэпу нужен низ; при питче ниже 0 частота поднимается `guardHz` — сэмпл не давит бас даже в −12). ВНИМАНИЕ: `GrainPlayer.start(time, offset)` в Tone 15 трактует offset как секунды ВОСПРОИЗВЕДЕНИЯ — реальная позиция в буфере = `offset × playbackRate` (grain-clock умножает аргумент). `trigger` поэтому передаёт `offset * stretch`; `spec.sync`-пэды (BEAT) дополнительно фазятся по лупу сессии: `trigger({phase, cycle})` входит в буфер на `phase/stretch` и лупит окно `cycle/stretch` секунд источника — тап посреди такта продолжает бит с текущей доли, а не с начала файла. Буферы грузятся с таймаутом 5 с — не приехал файл → пэд молчит, бут не ломается.
- `/src/audio/effects.js` — `createInstrumentBus` (по 3 эффекта на инструмент), `createDrumBus` (Dist/Cut/Room; в lite — только highshelf `air` +1.5 дБ @ 3 кГц + Cutoff + запечённый makeup вместо дефолтных drive/room), `createMasterFx` (Stutter/биполярный Cutoff LP+HP/8-bit/Wah; в lite — только Stutter и Cutoff), плюс FX-метаданные для UI (чипы, лейблы, цвета) и профиль `LITE`: флаги `lowPolyphony`/`singleFat`/`reducedFx`/`lowSampleRate`/`wideLookAhead`/`lowDpi`/`shortTails`/`coarseTouch`, читаются один раз при построении графа — урезанные узлы не создаются вообще, а не мьютятся. В lite (`reducedFx`) инструменты идут в сухую: выживает только Cutoff баса, ни одного конвольвера/дилея/хоруса не строится; DrumMachine при этом полный — все 7 WAV-сэмплов, никаких синтез-замен. `instrumentFxSpecs`/`drumFxSpecs` при `lite` возвращают `[]` — чипы и слайдеры не рисуются ни у хоста, ни у гостя; в Master-шите остаётся только громкость.
- `/src/audio/export-loop.js` — экспорт лупа: MIDI (SMF, PPQ 480, барабаны на канале 10; хиты семплера в MIDI не попадают — у них нет питча) и WAV через `Tone.Offline` (офлайн-рендер той же цепочки, включая master FX, громкость мастера и лимитер; `PadSampler` с текущим `sampleParams` создаётся только при `spec.includeSamples` — в шите это инверсия галочки «Keep meme samples out of WAV», которая по умолчанию стоит), repeats 1–128.

Под касанием подсвечивает активную колонку ступени и зоны аккордов (`zoneBounds`/`activeZone` через `setZones`/`setChordMode`); подсветку зон дублирует CSS-классами статичная разметка `#…-y-zones`. `setMarks` рисует записанные в луп ноты точками (одна на занятую колонку ступени; цвет инструмента у выбранного, серые `dim` у остальных), `setLitStep` подсвечивает точку жёлтым ореолом, пока её нота звучит (тёмная обводка остаётся всегда; ореол зажигает любая звучащая нота колонки, не только выбранного инструмента). Осторожно: хинт `desynchronized` у `getContext('2d')` на части мобильных GPU делает канвас непрозрачно-чёрным — не включать. Рендер инкрементальный: при неизменной «рамке» патчатся только полоски (см. раздел Г).

Слайдеры коммитят тихо (фаза `set` — никогда не триггерят звук), прослушка — только при выборе пэда/имени. В портрете панель в потоке под сеткой (ничего не перекрывает, страница скроллится — слайдеры не ветируют вертикальный жест), на десктопе/ландшафте — док в колонке инструментов, пэд держит размер. ## 3. Фактическая реализация модулей

### А. XY Touch Synth (synth.js, touch-pad.js)
- Пять инструментов: **Pad** (пул глайд-осцилляторов, fatsine), **Bass** (один моно-осциллятор, всегда одна нота, регистр на две октавы ниже; перекрытая нота возвращается после отпускания крышки), **Organ** (PolySynth sine4), **Kalimba** (FMSynth), **Synth** (глайд-пул, triangle). Алиас `piano` → `synth`. Пулы в полном режиме: pad 16, organ 16, kalimba 8, synth 12; в lite (флаг `lowPolyphony`): pad 8, organ 8, kalimba 4, synth 6; `singleFat` роняет `count` у fatsine пада и fatsawtooth баса до 1 (один осциллятор на ноту); `shortTails` режет release пада до 1.4 с.
- Режимы: `single` (одна нота по оси X) и `chords` (аккорд на ступени лада). У баса режим всегда single.
- Гармония: тональность (root, 12 нот), лады Major/Minor/Pentatonic, октава на инструмент (1–6). Расчёт частот — равномерная темперация `f = 440·2^((m−69)/12)`.
- В `chords` ось Y выбирает диатоническое расширение снизу вверх: triad → sus2 → sus4 → seventh → ninth; все тона остаются внутри лада. Лейбл аккорда (`Am7`, `Cmaj9`…) считает тот же `resolveGesture`, что и звук, — гость видит точное имя.
- Velocity зависит от Y и инструмента; аккорды пада приглушены относительно одиночных нот.
- Громкость голосов сначала выровнена по держащемуся RMS на уровне 0.8, потом докручена на слух (`volume`: pad −4, bass −1, organ −12, kalimba +2.5, synth −6.5 dB): орган посажен на −3 дБ, калимба поднята на +2.5 дБ — её пик одиночной ноты стал ровным с остальными голосами. У пада подъём +2 дБ отдан только одиночным нотам: аккордный duck в `#velocity` углублен 0.72 → 0.57, поэтому аккорды звучат ровно как раньше, а ноты стали громче. Шейпинг по режимам вынесен в таблицу `MODE_VELOCITY` (умножает базовый velocity): pad {chords 0.57, single 1.18}, kalimba {single 1.3} — одиночный щипок читается без аккорда, organ {chords 0.7} — стек голосов не давит микс.
- Новый живой аккорд «рубит» (choke) аккорды того же инструмента других пальцев — без длинного release-хвоста.

### Б. Драм-машина (drums.js, drum-grid.js)
- Дорожки: Kick, Snare, Hi-Hat, Clap (основной банк) + Open Hat, Tom, Cowbell (extra).
- Сэмплы — набор Roland TR-808 (Michael Fischer, 1994, «ABSOLUTELY FREE») с `cdn.jsdelivr.net/gh/fluid-music/open-drums/tr-808/TR808WAV` (scoped npm-URL с `@` jsDelivr отвечает 400). Таймаут загрузки 4 с на голос: не грузится → остаётся синтез (Membrane/Noise/Metal), пилюля на хосте показывает источник. Clap подрезается до пика (`clapTrimStart`), чтобы бить в сетку; у остальных сэмплов атака уже на старте (<1 мс), подрезка не нужна. Пулы по 4 `Player` на голос.
- Баланс голосов проверен замером peak/RMS через `Tone.Offline` (`scripts/balance/`): `SAMPLE_GAIN` = kick 1 / snare 0.78 / clap 0.45 / tom 0.78 / hat 0.68 / openhat 0.3 / cowbell 0.62 — kick опорный, спред пиков ≈5 дБ; open hat дополнительно приглушён — резал микс. Снейр — `SD/SD2575.WAV` (мощное мид-лоу тело + snap-слой): `playbackRate` 0.87 опускает питч в регистр старого снейра, а общая для обоих путей цепочка lowshelf 550 Гц / −3 дБ + highshelf 3000 Гц / −3 дБ прибирает середину/низ и смягчает верх, не теряя яркости. Клэп — `CP.WAV` с `playbackRate` 1.15 и кэпом длительности 0.24 с (`SAMPLE_DURATION`) — ярче и с тугим хвостом вместо длинного реверба; плюс общий air-shelf 2200 Гц / +3.5 дБ на обоих путях. `volume` синтез-fallback подобран под уровень своего сэмпла (kick −4, snare −5, hat −17, clap −3, openhat −17, tom −6, cowbell −20 dB). Характер синтеза подогнан под 808: open hat — тот же MetalSynth, что и закрытый, но decay 0.42 с / release 0.12 / octaves 0.6 (длинный звон вместо тика), том — MembraneSynth на B2 (~124 Гц, средний том, а не саб на A1) с drop две октавы за 45 мс. В lite драм-шина без Distortion и room-конвольвера: яркость дефолтного drive держит highshelf `air` 3000 Гц / +1.5 дБ, громкость — запечённый makeup (дефолтные wet'ы drive 0.4/room 0.17 × 0.93 ≈ 1.26); замер против полной шины — `scripts/balance/drum-lite-check.mjs` (RMS −0.2 дБ, air −0.5 дБ).
- Сетка: 16/32/64 шага (1/2/4 бара, по умолчанию 32 — два такта), `Tone.Sequence` на 16-е. Клетка циклится пусто → удар → триоль внутри этой доли → пусто.
- Пресеты: Four, Break, Offbeat, Jersey Club (32 шага, на чипе короткое «Jersey», полное имя в `title`), Trap (32 шага, роллы закрытого хэта — клетки `{ s, d: 3 }` в паттерне), Empty — ряд крупных чипов прямо на главном экране хоста (`#host-drum-presets`) и в футере гостя (`#controller-drum-presets-main`), дублируются в драм-шитах; смена бита в один тап через `pickDrumPreset` / `pickGuestDrumPreset`. Текущий подсвечен `is-picked`; ручная правка сетки снимает подсветку (`state.drumPreset` → `''`, `markDrumPreset`/`paintGuestDrumPreset` красят оба ряда). Repeat Off/1/2 бара зеркалит первые бары на остальные. Вход в редактирование — кнопка «Edit drums» с иконкой-карандашом (`#btn-drums` рядом с пресетами хоста, `#controller-drums` в футере гостя, у гостя имя пресета — второй строкой через `setIconLabel`).
- Редактирование: тап по клетке, драг-кисть по клеткам, режим записи Single/Triplet; зума-слайдера нет — пинч двумя пальцами и Ctrl/Cmd+колесо, драг панит ленту. Сложное редактирование (repeat-зеркала, длина лупа, триплеты, pitch ±12) спрятано за галочку «Advanced» в драм-шите и у хоста, и у гостя; без неё остаются пресеты и тап-набор. Pitch съезжает контролом `drumPitch` и живёт в `state.drums.pitch`.

### В. Эффекты (effects.js)
- У каждого инструмента своя шина с тремя эффектами (уровень Off/Low/High чипами + «More» — слайдеры деталей): Pad — Reverb/Delay/Chorus; Bass — Distortion/Cutoff(лопас)/Slap; Organ — Chorus/Vibrato/Room; Kalimba — Delay/Reverb/Reverse; Synth — Room/Delay/Chorus. У драм-машины отдельная шина Distortion/Cutoff/Room. На выходе шин всех инструментов, кроме баса, стоит highshelf 2200 Гц / −8 дБ — держит верх инструментов ниже полосы крэка снейра (~1.5–3 кГц).
- Ревербы инструментов — два ОБЩИХ конволвера на выходе `createInstrumentBus` (раньше было по конволверу на инструмент, 5 живых свёрток с драмами): **room** (decay 1.8 с — компромисс между старыми organ 1.6 / kalimba 1.8 / synth 2.2, preDelay 0.01) для organ/kalimba/synth и **hall** (decay 5.5 с, preDelay 0.02 — как был у пада) только для pad. Оба на `wet: 1` и выведены прямо в `mix`; у каждого инструмента свой send-`Gain(0)`, тап — с выхода `voiceGains` (после level/makeup/darken/audible-гейта: мьют обесточивает send, хвост дозвучивает естественно). Ползунок reverb/room крутит send-гейн через `sendLevel(wet, kind)` = `sin(wet·π/2) × makeupFromWets({kind})` — `wet` у Tone-эффектов это equal-power кроссфейд на StereoPanner (dry=cos, wet=sin), поэтому send повторяет синус-закон, а фактор makeup'а сохраняет хвосту уровень старой series-схемы. Драм-шина в полном режиме держит свой собственный room 0.9 с серийно (IR короткий и дешёвый) — вариант сенда в общий конволвер звучал заметно иначе; в lite конвольвера нет совсем. Итого живых конволверов 3 вместо 5 (в lite — 0). **В lite** конвольверы инструментов не строятся вообще — инструменты играют в сухую.
- **Lite-режим хоста** (`LITE` + флаг `lite` от `createHostView`): `reducedFx` не строит ни одного инструментального эффекта, кроме Cutoff баса — ни конвольверов, ни дилеев, ни хорусов/вибрато, ни send-гейнов; тот же флаг облегчает драм-шину (без Distortion и room: highshelf `air` +1.5 дБ @ 3 кГц + запечённый makeup) и мастер-шину (без 8-bit/Wah: crusher и wah-цепь не создаются, `setCrush`/`setWah` — no-op, в шитах только громкость). В `apply` соответствующие ключи гасятся ранним выходом (`if (!node) return`), так что контролы от устаревших гостей принимаются в `state.effects`, но в звук не идут; `lowPolyphony`/`singleFat` живут в `TouchSynth`, там же `shortTails` (release пада 1.4 с вместо 2.2). Второй заход урезаний: `lowSampleRate` — `AudioEngine` поднимает `AudioContext` на 24 кГц и отдаёт его Tone через `Tone.setContext` ДО `tone.start()`/`getContext()` (после создания контекста по умолчанию замена сиротит уже построенные узлы; старые браузеры могут отказать в опции `sampleRate` — тогда lite остаётся на частоте устройства). `setContext` перманентен для страницы: `#pickContext` отслеживает флагом `onLiteContext`, на чьём контексте сейчас Tone, и при входе в full после lite подсовывает назад device-rate контекст (`nativeContext` — захваченный у Tone `getContext().rawContext` ещё при lite-свопе, фолбэк — `new AudioContext()`; итого на странице максимум два контекста сколько ни переключайся) — иначе «полная» сессия молча рендерила бы 24 кГц; регрессия — `scripts/verify-context-swap.mjs`; `wideLookAhead` — `context.lookAhead` 0.05 с вместо 0.02; барабаны в lite играют теми же 7 WAV-сэмплами, что и full (меняется только шина — см. выше); `lowDpi` — `TouchPadRenderer` хоста с `maxRatio: 1.5`; `coarseTouch` — `throttleMs: 48` у хост-пада (~21 Гц вместо ~30); `cheapViz` — облегчённый рендер пада (см. touch-pad.js). Луп и редактор Notes в lite не урезаны — это main-thread цена, не аудио-поток. На шапке хоста lite виден пилюлей `lite` (`#host-lite-pill`), в лог пишется строка при старте аудио (с частотой контекста). Для отладки у engine есть геттер `sampleRate`.
- Reverse у калимбы — захват хвоста на `ScriptProcessor` и проигрыш буфера задом наперёд (AudioWorklet на `http://` в LAN недоступен, поэтому его нет в живом тракте).
- Компенсация громкости: wet-ветки СЕРИЙНЫХ эффектов уменьшают dry по таблице `WET_RETAIN`, а makeup-gain возвращает уровень. Реверб/room в makeup-модель не входят (send не приглушает dry, хвост добавляется сверху полного dry) — старая схема чуть перекомпенсировала dry (реальный кроссфейд equal-power, а модель линейная), поэтому чистый dry сейчас до ~1 дБ тише, хвост — того же уровня; замером `scripts/balance/reverb-send-check.mjs` разница по held/tail в пределах ~1.5 дБ. Cutoff на 0 — настоящий байпас.
- Мастер-эффекты (после микса, до лимитера): **Stutter** (удерживаемый срез 1/4–1/32 через FeedbackDelay на полном уровне; узел один на весь `createMasterFx`, maxDelay 2с — захват лишь переписывает `delayTime`/`feedback` через `setValueAtTime`, аудио-узлы на горячем жесте не создаются), **Cutoff** — биполярная пара общего тракта: lowpass 14000→180 Гц ниже середины Y и highpass 24→4000 Гц выше неё, взаимоисключающиеся, оба на 0 — настоящий байпас, короткий рамп против зипперинга; **8-bit** (WaveShaper-квантизатор, без лифта), **Wah** (бандпас 160→2400 Гц с лифтом ×4.8). Stutter и Cutoff живут на главном экране: чипы Notes/FX переключают пад — в FX-режиме X делит пад на `FX_PAD_DIVISIONS` (первая зона — только фильтр без статтера, остальные держат статтер на своём делении), Y — биполярный фильтр с мёртвой зоной по центру, отпускание гасит статтер и открывает фильтр. Мастер-шит: 8-bit, Wah и громкость мастера (`engine.setMasterVolume`, гость шлёт `masterFx.volume`); Wah живёт только в шите — при рассылке `host:state` инпут, за который сейчас держатся, не перезатирается.
- У каждого голоса, включая барабаны, флаги Mute/Solo.

### Г. Лупы и редактор Notes (synth.js PerformanceRecorder, piano-roll.js)
- Луп пишет только ноты (on/up), квантованные к сетке 16-х `Tone.Transport`: один `scheduleRepeat('16n')`-тик на рекордер (якорь на тике 0 — Tone сам ресинкает repeat на start/seek) проигрывает события текущего шага из индекса `#byStep` (step → events[]). Правки лупа переписывают только Map (`#put`/`#unindexEvent`/`#moveEventStep`, полная пересборка в `setLoopSteps`), таймлайн транспорта не трогают — плотный луп держит одну live-запись (`scheduledCount` = 0/1) вместо 2×событий; тик снимается, когда `#events` пуст. `on` без парного `up` (тейк ещё держат или off потерян) в `#perform` не звучит вовсе — иначе нота висла бы весь цикл; при закрытии тейка звучащие `loop:`-голоса глушатся сразу. У `up`-события может быть поле `frac` ∈ [0,1) — доля шага, на которую `#perform` сдвигает релиз: так записываются gate-пэды семплера — `captureHit` квантизирует только начало, а `captureRelease` (отпускание пальца/`stop()` рекордера) кладёт `up` на шаг реального отпускания с дробным `frac` — хит звучит ровно столько, сколько держали, до квантизации. Отпускание также гасит уже звучащий `loop:`-голос этого тейка (`release('loop:<player>:<voice>')`, то же правило, что у `#silenceTake` для нот) — иначе нота, успевшая войти по записанному `on`, доигрывала бы до `up` следующего круга и gate-пэд «залипал» после отпускания пальца. Инвариант высоты: записанные ноты хранят только `degree` (scale-relative — следуют за октавой/тональностью/ладом, аккорд регенерируется на воспроизведении); точный `midi` в событии допустим только для высоты вне лада — `resolveGesture` при наличии `midi` идёт «точным» путём: игнорирует октаву/лад и схлопывает аккорд в одну ноту. Редакторские правки (драг `moveSharedGroup`, тап `onPlace` у обеих ролей) поэтому пишут `degree` и стирают `midi`, когда `pitchChoice(...).distance === 0`. События дублируются в индекс `#byVoice` (`voiceId → { ons, up, seq }`): все lookup «события этого голоса» идут через него, а не `filter`/`find` по `#events` — важно на хот-пассе `capture()` (30 Гц move на палец). `notes()` кэширует собранные строки в `#notesCache` (инвалидируется любой правкой `#events`), тай-брейк сортировки — числовой `seq` (порядок создания голоса) вместо `localeCompare`.
- Длина лупа: 2 → 4 → 1 бара кнопкой «N bars». Аккорд сохраняется группой степеней лада; слайд пальцем режет полосу на сегменты по питчам.
- Лупы общие: хост рассылает `loopNotes` всех игроков в `host:state`, редактор Notes у всех показывает одну партию. Пayload несёт счётчик `v` (инкремент в `shareLoop`), по нему гость пропускает пересборку нот на идентичных эхо. `shareLoop()` вызывается через дебаунс `queueLoopPush` (~80 мс, по образцу `queueDrumPush`) — вспышка записанных при слайде нот схлопывается в одну рассылку; `flushLoopPush()` на stop/clear/clear-inst/undo/redo отсылает состояние немедленно, чтобы гости не видели отставания. Сам лист тоже не пересобирается на каждую ноту: `renderPianoRoll` хранит «рамку» (rows/шаги/stepPx/инструмент/owner/маска лада) в `scrollEl.__frame` — совпала, значит `patchRollNotes` диффит только полоски по ключу `voiceId@midi` и подписи `__sig` (неизменная полоска держит элемент, биндинги и выделение; плейхед/марки/скролл не трогаются), разошлась — полный ребилд. Пока идёт тейк, `refreshLoops(true)` на хосте красит открытый шит по таймеру ~180 мс (`queueHostRoll`; стоп/undo/ручные правки зовут eager-вариант, а `paintHostRoll` гасит висящий таймер), гость при любом `loopNotes.players[].recording` откладывает `paintGuestNotes` на такой же таймер — новая нота появляется ≤ ~0,25 с. Чужие ноты — пунктиром, но редактируются так же: правки гостя идут контролами `eraseNote`/`moveNote`/`moveGroup`/`addNote` на хост, хост находит владельца по `voiceId` и пишет в его рекордер. Записанные ноты видны и на тач-паде: `syncPadMarks` (хост и гость) кладёт в `renderer.setMarks` метки `padNoteMarks` — точки колонок, где есть ноты, по центру колонки (высота касания не показывается — в chords-режиме разброс по Y вводил в заблуждение). Октава позицию не меняет, но при совпадении нот разных октав в одной колонке точки стопкой лежат друг на друге: слой на каждую октаву, нижняя (большая) под верхней (маленькая, `MARK_BASE_RADIUS` = обычный размер всех одиночных точек — без наложения размер не зависит от октавы). Слой выбранного инструмента — его цвет, чужие — серые; несколько октав одного инструмента — все цветные. По `host:pulse`/`onStep` звучащий слой получает жёлтый ореол (`ranges` — `{ s, e, o }` на ноту, ореол не затемняется у чужих инструментов); размер и тёмная обводка при проигрывании не меняются.
- История: Undo/Undo all/Redo, очистка и Rec/stop у каждого игрока. Стрелки ⟲/⟳ в плей-баре и в шите — откат/накат только СВОИХ правок (`ownPast`/`ownFuture` по editorId — redo тоже личный, накатывает только свои отмены; «Undo all» откатывает последнюю правку на листе вообще, а редо за ней остаётся у автора правки). Записанный с пада тейк (жест палец-вниз→палец-вверх, включая слайды и смену вида аккорда на лету) — отдельная запись истории: рекордер при закрытии тейка зовёт `onTake`, отдавая снапшот лупа до первого note-on тейка плюс события тейков, закрывшихся, пока он был открыт (`#takePre`/`#closedLog`) — undo снимает ровно один жест, не всю сессию записи. Каждая правка лежит и в личном стеке (до 40), и в общем `globalPast` (до 120): любой undo снимает её из обоих (`dropEntry`), redo возвращает в оба — поэтому undo не «застревает» после первого применения. Очистка: тап по `clr` чистит только свой луп, удержание ≥600 мс — все лупы (`is-arming` заполняет кнопку); `clear inst` в шите убирает инструмент только из своего лупа; очистка пустого лупа записи в истории не оставляет. Удержание кнопки ⟲/⟳/Undo all подсвечивает затрагиваемые ноты (`bindHistoryPreview` → `previewTargets`: дифф снапшота по ключам `voice:step:type` → жёлтое кольцо на точках пада `setUndoPreview` и рамка `is-undo-preview` на полосках ленты `setRollUndoPreview`). Undo/redo, попадающий в середину открытого тейка, НЕ останавливает запись — тейк продолжает писать, а зажатый палец после восстановления просто начинает новую ноту (его 'up' закрывает её, сиротские note-off отбрасываются); Rec-чип гостя синхронизируется по `loopNotes.players[].recording`.
- Транспорт: Play/Stop, BPM-пресеты 80/96/120/140 (клэмп 40–200). Хост шлёт volatile `host:pulse` с номером шага — у гостей ползет плейхед, номер бара и биты-точки.

### Д. Экспорт (export-loop.js)
- `MIDI` — SMF-файл лупа ×N повторов: ноты всех инструментов по каналам, барабаны на канале 10 (GM-ноты).
- `WAV` — офлайн-рендер (`tone.Offline`, 44.1 кГц, стерео) той же цепочки: инструменты и барабаны → master → compressor → masterFx → limiter. Учитываются mute/solo, уровни и master FX.
- Repeats: целое 1–128.

### Е. Сеть и сессии (server.js, socket.js)
- События: `host:create` → 4-символьный код (алфавит без похожих букв; повторный `host:create` с того же сокета сначала закрывает его прежнюю комнату — повторный emit из ретрая `#request` не должен оставлять сиротскую сессию с мёртвым хостом), `controller:join` (код + имя), `controller:touch` (move летит volatile), `controller:control` (все настройки гостя: инструмент, эффекты, октава, луп, барабаны — включая `drumLength`/`drumPitch`, BPM, транспорт, мастер-FX, правки нот, `history` undo/redo, превью высоты, контролы семплера `sampleHit`/`sampleSolo`/`sampleTune`/`sampleTuneDone`/`samplePreview`; непрерывные — `masterFx`/`effect`/`level`/`octave`/`drumPitch` — летят volatile и коалесцируются через `sendControlThrottled`, остальные — надёжно через `sendControl`), `host:state` (хост мержит каждый патч в накопленное `#shared`, но шлёт наружу только сам патч — `lite`-флаг профиля, тональность, готовность, лупы, барабаны, masterFx; зеркала непрерывных контролов — гостевые masterFx/level/effect/octave и FX-пад хоста — через дебаунс ~90 мс `queueHarmony`, а полный снапшот `#shared` уходит `broadcastSnapshot()` на `peer:join`, чтобы поздний гость получил всё сразу), `host:pulse`, `peer:join`/`peer:leave`, `session:closed`.
- QR на хосте открывает `http://<lan-ip>:43117/?role=controller&code=XXXX` — код руками не вводится; для localhost хост подставляет LAN-IP из `/api/lan`. В шапке живёт компактный QR-стамп (вся `.qr-card` — `div[role=button]`); один тап по ней открывает шит **Invite** (`#host-share-sheet`, z-index выше сплэша «Sound is off») с крупным QR на белой карточке с quiet zone (`min(72vw, 60dvh, 320px)`, рендерится на 512px), кодом сессии и выделяемой текстовой ссылкой. На телефоне в landscape карточка перестраивается в две колонки: QR слева, код/ссылка/Done справа. У контроллера share/QR нет — он сам гость.
- Отключение хоста закрывает сессию для всех; уход гостя глушит его голоса (`releaseMatching` по префиксу peerId).

### Ж. Мобильный UI и правила
- Тач-пад: `touch-action: none`, запрет `contextmenu`/`selectstart`/двойного зума, `gesturestart` preventDefault. Пад хоста и гостя занимает максимум площади.
- Все переключатели — крупные chip-кнопки; слайдеры только в детальных шитах. Зум в редакторах (Notes и Drums) — только жестами: пинч, Ctrl/Cmd+колесо, драг-пан; видимых кнопок и ползунков зума нет. Никаких мелких крутилок.
- На живых экранах `<button>` заменяются на `div[role=button]` — иначе iOS вибрирует при каждом тапе (`quiet-touch.js`).
- Кнопки и чипы — иконка + короткий лейбл через `paintIconButton`/`setIconLabel`/`chipIcon` (`src/ui/icons.js`): плей-бар Notes/Chords + Rec/undo/redo/clr, переключатель пада Notes/FX (нота и ножницы — ножницы = статтер), экшены шитов (Undo/Redo/Done/clear inst). Полные имена эффектов (`FX_FULL_LABELS`) показываются только в шите деталей — там есть место. Длинные строки давятся `text-overflow: ellipsis` (пресеты, заголовки шитов, `#controller-key`), на ≤480px чипы плей-бара ужимают шрифт.
- Правила производительности, которые стережёт стенд: перерисовка только по событиям, тачи в сеть ≤30 Гц и только при реальном сдвиге, непрерывные контролы ≤~20 Гц через `sendControlThrottled` (volatile + trailing), гость не перестраивает DOM на эхо-патчах `host:state` (diff `effects`/`octaves`/`drums`, версия `v` у `loopNotes`), аудио-узлы создаются один раз при старте — на касание идут только триггеры и установка параметров.
- Весь код инструмента написан с нуля на стандартах W3C под MIT. Исключение — сэмплы TR-808: бесплатный набор «без ограничений», но это не MIT (см. README § «Барабаны»). Файлы в `samples/` — пользовательские мем-ассеты плюс скрэтч с Pixabay (происхождение каждого — README § «Семплер: откуда сэмплы»), отдаются whitelist-маршрутом `/samples`.

### З. Семплер (sampler.js, sample-grid.js)
- Третий режим пада **SMP** между Notes и FX (иконка-сетка `chipIcon`, чип `pad-sample`): на месте тач-пада появляется оверлей `#host-sampler`/`#controller-sampler` с сеткой 4×3 — восемь one-shot пэдов (**BRUH**, **FAH**, **BOOM**, **WOW**, **MEOW**, **BARK**, **BONK**, **PEANUT**), три gate (**SCR 105** — прибит к BPM, **OMG** и **BEAT** — бум-бэп-луп 90 BPM в 4 такта, темполочен и фазой привязан к позиции лупа: тап посреди бара продолжает бит с текущей доли, крутит столько тактов, сколько в сессионном лупе — все звучат, пока палец на пэде) и пэд **SOLO**; над сеткой красная пометка о некоммерческом использовании (`.sampler-note`). Режим доступен и хосту, и гостям; работает и на lite-хосте (пара лёгких GrainPlayer-пулов не грузит). Контейнер оверлея — `.pad`, на нём живёт `position: relative` + `overflow: hidden`, сетка фиксируется `inset: 10px 0` (10px прикрывают скругление углов пада).
- Хиты пишутся в луп рекордером вместе с нотами: `captureHit(sample)` кладёт событие с `instrument: 'sampler'` и полем `sample`; one-shot — одношаговый on+up, gate — `on` на квантизированном шаге + `up` с `frac` на реальном отпускании (`captureRelease`, открытые захваты живут в `#openHits` по sampleId). `notes()` отдаёт `sample` рядом с `midi`/`step`, `moveNote`/`addNote`/`clearInstrument('sampler')` работают с теми же правилами и историей. Нота-полоса семплера — `roll__note--sampler`, в редакторе они видны на лейне своего имени; SOLO в луп не пишется — это транзиентное состояние.
- Воспроизведение лупа: `recorderFor` передаёт в `perform` хэндлер `sampleHit`, который в реальном времени зовёт `sampler.trigger`, а в `Tone.Offline`-экспорте — тот же `PadSampler` на офлайн-контексте (`reuseContext: true`, `await ctx.loaded()`). Solo-состояние и настройки пэдов в луп не входят.
- SOLO — гейт-пэд: пока держат, `setAudible(false)` всем шинам инструментов и драм-машине, семплер продолжает звучать; на отпускании — `refreshAudible` вернёт прежнее состояние из mute/solo состояния. У хоста состояние соло-гостя (`who` = peerId, `sampleSolo[id] = on`) тоже красится на сетке `setSoloRemote` и уходит в `host:state.sampleSolo` — другие гости видят зажатый пэд. При отключении сольника (`clearPeer`) его соло гасится, сетка и bus'ы сбрасываются.
- FX-семантика: захват статтера/фильтра (Notes→FX-пад) при держащемся сэмпле/соло работает по-другому на разных ролях — у хоста `performHit`/`setSampleSolo` вызывают `fxKnock()`, который отпускает внешний FX-холд (активация сэмплера сбивает чужой FX-жест); обратно нет — если семплер уже держится, новый FX-холд применяется и к сэмплеру, т.к. `PadSampler` идёт через `engine.master` → compressor → masterFx.
- Кнопка редактирования (`#host-sample-edit`/`#controller-sample-edit`) — одна кнопка `✎ Edit` (карандаш покрывает и тюнинг, и стирание; на узких экранах подпись прячется — `sample-edit-btn`): включает/выключает объединённый edit-слой — пэды в фиолетовом кольце тюнятся драгом (дабл-тап/колесо — ресет и точные шаги), а красный ✕ в углу пэда стирает его хиты из всех лупов (✕ глух к нажатиям посреди tune-жеста). Пока слой редактирования активен, Rec приглушён (`is-off`) — пэды не пишутся. Выход из режима семпла НЕ обрывает звучащий ваншот (`stopAll` на смене padMode не вызывается — только park/destroy/peer-leave). Выбор инструмента (`pickInstrument`/`pickGuestInstrument`) — интент играть: пад возвращается в Notes, режим принудительно single, даже если стояли аккорды или SMP/FX. У хоста `sampleTune` пишется в `sampler.setParams` (моментально на звучащих слотах) и в `state.sampleParams`, которые уходят гостям в `host:state` — бейджи синхронятся у всех; `sampleTuneDone` (`quiet: true` у колеса/дабл-тапа — без прослушки) флашит актуальные параметры (`queueHarmony`-дебаунс не нужен — значения летят при `shareState`-сборке). Добавление нового сэмпла — хардкод в `SAMPLE_BANK` + файл в `samples/` + ячейка в `SAMPLER_PAD_CELLS` (порядок на сетке по `r1cX`).
- Редактор Notes: при инструменте `sampler` в `paintRollInstrument` ролл переключается на `lanes` — ряды-имена пэдов без питч-сетки, `paintHostRoll`/`paintGuestNotes` передают `lanes: SAMPLE_BANK`, tap ставит хит своей дорожки, тап по имени — `onAudition`/`samplePreview` (гость слышит пэд, не заходя в режим семплера), `pr-note--sampler` не двигается по вертикали и не тянет resize.

## Запуск
```bash
npm install
npm run dev   # http://127.0.0.1:43117
```
Хост: `/?role=host` → «Start sound»; lite-хост: `?role=host&lite=1`. Гость: QR или `/?role=controller&code=XXXX`. Публичная версия — статика на GitHub Pages + Socket.io на Render.

## Убрано — не возвращать
- AudioWorklet-reverse в живом тракте — недоступен на `http://` в LAN; живой reverse у калимбы на `ScriptProcessor` (`createTailReverse`).
- `Effect` / `EffectChain` / `WahWahEffect` / `ReverseEffect` (AudioWorklet) и `ensureReverseWorklet` — мёртвый легаси-модуль, удалён из `effects.js`; живой путь — `createInstrumentBus` / `createDrumBus` / `createMasterFx`. Не возвращай его.
- Инструмент «piano» переименован в «synth»; алиас остался только в `normalizeInstrument` для совместимости со старыми лупами.
- Wah-Wah, модулируемый осью Y тач-пада гостя — в живом тракте такой связи нет; мастер-wah крутится слайдером.
