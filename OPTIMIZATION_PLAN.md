# План оптимизации DoggoJam

> Снимок анализа кода от 2026-09-28. Цели: слабый телефон как хост (CPU в аудио-графе и на main thread), телефоны гостей (сеть, DOM, размер загрузки), сервер на Render (бесплатный тариф — каждый байт и тик на счету).
> У проекта уже есть стенд замера: `npm run dev` + `node scripts/perf-probe.mjs --url http://127.0.0.1:43117 --label <tag>` → `/tmp/perf-<tag>.json`. Снимай `before` до любых правок и `after-*` после каждого шага.

## Что реально грузит систему (по убыванию эффекта)

### А. Сеть / рассылка состояния — главный перерасход

1. **`broadcastState` шлёт ВЕСЬ накопленный `#shared`**, а не патч. Любой `publishHarmony()` несёт заодно последний `loopNotes` и всю драм-сетку всем гостям — `src/network/socket.js:187-190`.
2. **При 30 Гц FX-пада гостя хост рассылает полное состояние на ~30 Гц.** Цепочка: `driveFxPad` (controller.js:902, `sendControl` на каждый move) → сервер → `applyGuestMaster` (host.js:2199) → `publishHarmony()` → broadcast всем гостям. Дебаунс `queueHarmony` (host.js:1094) уже существует, но гостевые контролы его не используют.
3. **Слайдеры гостя шлют `sendControl` на каждый `input` (~60 Гц)**: masterFx (controller.js:830), effect (695), level (650), octave (672), drumPitch (629). На хосте это ещё и `renderFxSliders()`/публикации.
4. **Каждый `host:state` у гостя пересобирает DOM**: `renderGuestFx()` — `replaceChildren` на любой payload с `effects`, даже когда шит закрыт (controller.js:974-977); `syncPadMarks()` + `paintGuestNotes()` по тем же путям.
5. `shareLoop()` (host.js:1620) считает `recorder.notes()` по ВСЕМ игрокам + broadcast всей карты на каждую записанную ноту — во время слайда по сетке это на каждый шаг.

### Б. Аудио-граф хоста — главный CPU

6. **5 конволверных ревербов крутятся всегда** (pad 5.5 c!, organ 1.6, kalimba 1.8, synth 2.2, drums 0.9): ConvolverNode считает свёртку даже при `wet: 0`, а дефолты (`defaultFxState`, effects.js:489) у большинства ВКЛЮЧЕНЫ. На телефоне это самая дорогая часть тракта.
7. **Статтер создаёт и убивает `FeedbackDelay` на каждый захват** (effects.js:1212-1244 `capture()`/`dropDelay()`) — прямое нарушение собственного правила «узлы создаются один раз».
8. Пулы голосов: pad = 16 × `fatsine×3` осцилляторов, synth 12, organ PolySynth 16, kalimba FMSynth 8 — на аккордах по 5 нот это десятки одновременных осцилляторов. `oversample: '2x'` у Distortion (bass + drums) удваивает частоту waveshaper'а.
9. ~~**Каждая записанная нота = два `transport.scheduleRepeat`**~~ — сделано: один `scheduleRepeat('16n')`-тик на рекордер читает шаги из `#byStep`; `scheduledCount` = 0/1 вместо 2×событий.
10. `createTailReverse` (ScriptProcessor, effects.js:533+) — main-thread аудио-коллбек, живёт пока wet>0 у калимбы.

### В. Запись лупа — O(n) на каждый тач

11. `recorder.capture()` на каждый move (30 Гц) делает `#events.filter(...)` (synth.js:1271, 1363, 1400, 1490-1500 и др.) — линейные сканы по всем событиям лупа на каждое движение пальца каждого игрока.
12. `notes()` сортирует `localeCompare` (synth.js:1724) и пересобирается на каждый `refreshLoops`.

### Г. Загрузка страницы

13. **Tone.js грузится синхронно в `<head>` ДЛЯ ВСЕХ** (index.html:16) — это ~1.5 МБ неминифицированного UMD на каждый телефон-гость, который аудио вообще не использует (ленивые импорты есть, но скрипт-то уже скачан и распарсен). Socket.io тоже грузится до выбора роли.
14. `sw.js` перехватывает каждый GET и проксирует `fetch` — лишний хоп на каждый запрос (кэша нет по определению). Для installable-критерия достаточно пустого `fetch`-листенера.
15. Express: нет gzip (`compression` не подключён); `express.static(ROOT)` отдаёт вообще всё, включая `node_modules`, `scripts`, `PROMPT_CONTEXT.md`.
16. Мусор: файл `nul` в корне (артефакт Windows-команды); ~430 строк мёртвого легаси в effects.js (строки 8-437: `Effect`, `DelayEffect`, `ReverbEffect`, `DistortionEffect`, `REVERSE_PROCESSOR`, `ensureReverseWorklet`, `reverseNodeClass`, `ReverseEffect`, `WahWahEffect`, `EFFECT_CLASSES`, `EffectChain`) — живой тракт их не использует, в `PROMPT_CONTEXT.md` они помечены «не возвращать».

### Д. UI-рендер

17. `renderPianoRoll` — полный `replaceChildren` всей разметки на каждый вызов (piano-roll.js:159). Пока шит закрыт — защищено; при открытом шите во время записи перестраивается на каждую ноту.
18. `createDrumGrid.render()` пересоздаёт все кнопки; зато есть `paintCell`/`paintAll` — `applyHostDrums` у гостя и изменения длины ходят через полный render. Допустимо, но на списке улучшений.
19. `paintZone`/`renderer.update` на каждый move — мелочь, канвас и так по rAF.

## Порядок шагов (почему именно такой)

Принцип: сначала измерить и убрать дешёвое/безрисковое, потом сеть (эффект виден сразу на всех устройствах), потом аудио-граф (риск изменить звук — проверять ухом), потом структуры данных, в конце — продуктовое решение о lite-режиме.

| # | Шаг | Эффект | Риск | Зависит от |
|---|-----|--------|------|-----------|
| 0 | Базовая линия + гигиена (`nul`, sw.js, dead code, compression, static whitelist) | Средний (загрузка, гигиена) | Низкий | — |
| 1 | Ленивый Tone.js: грузить только при входе в host | Огромный для гостей (~1.5 МБ + парсинг) | Низкий-средний | 0 |
| 2 | Сеть: `broadcastState` шлёт только патч; mirror-поля через `queueHarmony` (~100 мс); полный снапшот — на `peer:join` | Огромный (убирает 30 Гц полного состояния) | Средний | 0 |
| 3 | Троттлинг контролов гостя (input→emit ≤ 20-30 Гц, volatile для непрерывных) + гард `renderGuestFx` | Большой | Низкий | 2 |
| 4 | ~~Хот-пасс записи: индекс `#byVoice`, кэш `notes()`, дебаунс `shareLoop` как `queueDrumPush`, убрать `localeCompare`~~ — сделано | Большой на слабом хосте при записи | Средний | — |

### Чат 6 — Ревербы: общая send-шина

```
[вставить общий блок контекста]
```

## Заметки и риски

- **Не сваливать всё в один чат.** Шаги 2+3 и 4+7 пересекаются по файлам — делать последовательно или одним исполнителем.
- Замерять на одном и том же сценарии и одном устройстве, иначе сравнения бессмысленны. perf-probe пишет `/tmp/perf-<label>.json` (на Windows — temp-директория ОС).
- `lookAhead = 0.02` (engine.js:81) — агрессивно маленький; если после шагов появятся дропауты на слабом хосте, это первый подозреваемый для поднятия до 0.05.
- Звук ревербов и статтера — субъективно «правильный» сейчас; шаги 5-6 мерить и слушать, diff держать обратимым.
- GitHub Pages + Render: помни, что публичный бэкенд отдельный — изменения протокола (шаг 2) должны быть совместимы со старым сервером, пока Render не обновлён, либо катать вместе.
